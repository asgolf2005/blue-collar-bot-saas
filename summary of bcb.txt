1. EXECUTIVE SUMMARY
================================================================================

PROJECT NAME: Blue Collar Bot (BCB)
TAGLINE: "The AI-Powered Field Service Management Platform for Trade Businesses"
MISSION: Democratize enterprise-grade field service management for small-medium
trade businesses by combining modern CRM capabilities with AI-powered phone
reception at a fraction of competitor pricing.

VISION: Become the #1 alternative to ServiceTitan for businesses with 1-20
technicians by 2027, with a target of 500+ paying customers generating $150K+
MRR.

CURRENT STATUS: Production Beta - Core features complete and deployed. Platform
is serving real customers with AI phone receptionist integration active.

UNIQUE VALUE PROPOSITION:
- 70% cheaper than ServiceTitan ($299 vs $1,500+/month)
- AI phone receptionist included (competitors don't offer this)
- Modern, mobile-first UX
- 15-minute setup vs 6-week implementation
- No long-term contracts

FOUNDER NOTES:
This project was built to solve a real problem: small trade businesses are
forced to choose between expensive enterprise software or piecing together
multiple tools. The AI phone receptionist was the breakthrough insight - it's
not just software, it's a complete business operations replacement.

2. PROBLEM STATEMENT & MARKET OPPORTUNITY
================================================================================

THE PROBLEM:
Small-medium trade businesses (1-20 technicians) face a critical dilemma:

1. EXPENSIVE ENTERPRISE SOLUTIONS:
   - ServiceTitan: $1,500-$3,000/month + setup fees
   - HouseCall Pro: $200-$500/month (limited features)
   - FieldEdge: $1,200+/month
   - Require 6-12 week implementations
   - Lock-in contracts (annual minimums)

2. DIY APPROACH PAIN POINTS:
   - Google Calendar + spreadsheets (no automation)
   - Missed calls = missed revenue ($500-2,000 per missed job)
   - Manual dispatching (inefficient, error-prone)
   - No customer self-service portal
   - No real-time visibility into technician locations
   - Payment collection is manual and slow

3. THE HIDDEN COSTS:
   - Receptionist salary: $3,000-4,000/month
   - Missed calls: 30-40% of after-hours calls go unanswered
   - Administrative overhead: 10-15 hours/week on scheduling
   - Payment delays: 45-60 days average collection time

MARKET SIZE:
- Total Addressable Market (TAM): $12B field service management software
- Serviceable Addressable Market (SAM): $2.5B (small-medium trade businesses)
- Serviceable Obtainable Market (SOM): $125M (2% of SAM, realistic 5-year goal)

TARGET CUSTOMER PROFILE:
- Industry: Plumbing, HVAC, Electrical, Handyman, Appliance Repair
- Size: 1-20 technicians, 1-5 office staff
- Revenue: $500K-$5M annual
- Pain Points: Missing calls, scheduling chaos, slow payments
- Tech Comfort: Moderate (use smartphones, not necessarily tech-savvy)

3. SOLUTION OVERVIEW
================================================================================

BLUE COLLAR BOT is a comprehensive SaaS platform with three core components:

┌─────────────────────────────────────────────────────────────────────────────┐
│                         BLUE COLLAR BOT PLATFORM                            │
├──────────────────┬──────────────────┬──────────────────┬────────────────────┤
│   AI RECEPTIONIST │   ADMIN DASHBOARD │  TECH MOBILE APP │  CUSTOMER PORTAL  │
├──────────────────┼──────────────────┼──────────────────┼────────────────────┤
│ • Answers calls   │ • Job management  │ • Today's jobs   │ • Book online     │
│   24/7            │ • Scheduling      │ • Update status  │ • View appointments│
│ • Books jobs      │ • Invoicing       │ • Upload photos  │ • Pay invoices    │
│   automatically   │ • Analytics       │ • GPS tracking   │ • Track technician│
│ • Creates         │ • Team management │ • Navigation     │ • Job history     │
│   customers       │ • Customer DB     │ • Offline mode   │ • Messaging       │
└──────────────────┴──────────────────┴──────────────────┴────────────────────┘

COMPONENT DETAILS:

1. AI RECEPTIONIST (Unique Differentiator)
   - Integration: n8n workflow automation
   - Capabilities:
     * Answers business calls 24/7
     * Understands service requests using NLP
     * Collects customer information
     * Books appointments based on technician availability
     * Sends confirmation SMS/email
     * Creates job and customer records automatically
   - Fallback: Voicemail transcription + immediate notification

2. ADMIN DASHBOARD
   Role: Business owner, office manager, dispatcher
   Access: /admin/*
   Key Features:
   - Real-time job board with status tracking
   - Drag-and-drop dispatch board (planned)
   - Calendar with multiple views (Month, Week, Day, Map)
   - Customer CRM with full history
   - Invoice creation and management
   - Payment processing via Stripe
   - Analytics dashboard (revenue, performance)
   - Team management and permissions
   - Service catalog with pricing

3. TECHNICIAN MOBILE APP
   Role: Field technicians
   Access: /tech/*
   Key Features:
   - Mobile-optimized "Today's Jobs" view
   - One-tap status updates (5 statuses)
   - Photo upload (before/during/after)
   - GPS location sharing (live tracking)
   - Customer contact with one-tap call/navigate
   - Offline mode (work without signal)
   - Weekly schedule view
   - Performance stats and earnings

4. CUSTOMER PORTAL
   Role: End customers
   Access: /customer/*
   Key Features:
   - View upcoming and past appointments
   - Real-time technician tracking (when en route)
   - View job photos and status
   - Access and pay invoices online
   - Update contact information
   - Request new services

4.2 FRONTEND ARCHITECTURE

FRAMEWORK: Next.js 16.1.0 with App Router
RENDERING STRATEGY:
- Server Components (default): Data fetching, initial render
- Client Components: Interactivity, real-time features, forms
- Server Actions: Form mutations without API routes

STATE MANAGEMENT:
- Server State: React Server Components + cache
- Client State: React hooks (useState, useReducer)
- Global State: URL params for shareable state
- Real-time: Supabase Realtime subscriptions

ROUTING STRUCTURE:
```
app/
├── (marketing)/        # Public marketing pages
├── admin/              # Admin dashboard (protected)
│   ├── jobs/
│   ├── customers/
│   ├── invoices/
│   ├── calendar/
│   ├── analytics/
│   └── settings/
├── tech/               # Technician interface (protected)
│   ├── dashboard/
│   ├── today/
│   ├── schedule/
│   ├── jobs/[id]/
│   └── stats/
├── customer/           # Customer portal (protected)
│   ├── appointments/
│   ├── invoices/
│   └── profile/
├── api/                # API routes
└── layout.tsx          # Root layout
```

COMPONENT ARCHITECTURE:
- components/ui/         # Design system primitives
- components/admin/      # Admin-specific components
- components/tech/       # Tech-specific components
- components/customer/   # Customer portal components
- components/shared/     # Cross-cutting components

4.3 BACKEND ARCHITECTURE

DATABASE: PostgreSQL 15+ (via Supabase)
SCHEMA DESIGN: Multi-tenant with business_id isolation
SECURITY: Row Level Security (RLS) on all tables

KEY DATABASE FEATURES:
- 20+ tables with relationships
- 14 migration files (versioned schema)
- Triggers for automated notifications
- Functions for complex aggregations
- Indexes for performance optimization
- Full-text search on customers/jobs

REAL-TIME ARCHITECTURE:
- Supabase Realtime for live updates
- Channels: job_updates, notifications, tech_locations
- Broadcast events: status changes, new jobs, payments

FILE STORAGE:
- Supabase Storage buckets
- job-photos: Public access for easy sharing
- 50MB file size limit
- Image and video support

5.5 DATABASE FUNCTIONS

generate_invoice_number(business_id UUID) → TEXT
  Auto-generates invoice numbers: INV-YYYY-XXXXX

create_notification(user_id, type, title, message, link) → UUID
  Creates notification record, bypasses RLS

get_latest_tech_locations(business_uuid UUID) → TABLE
  Returns most recent location for each tech in business

notify_tech_job_assigned() → TRIGGER
  Automatically notifies tech when job assigned

update_updated_at_column() → TRIGGER
  Updates updated_at timestamp on row changes

5.6 ROW LEVEL SECURITY (RLS) POLICIES

All tables have RLS enabled. Key policies:

users table:
  - Users can view own profile
  - Admins can view all users in their business
  - Users can update own profile (except role)

jobs table:
  - Admins can CRUD all jobs in their business
  - Techs can view/update assigned jobs
  - Customers can view their own jobs

technician_locations table:
  - Techs can insert own location
  - Admins can view all locations in their business
  - Customers can view tech location for their assigned job

7.2 KEY API PATTERNS

AUTHENTICATION:
- All API routes use Supabase Auth session
- Server-side: await supabase.auth.getUser()
- Returns 401 if unauthenticated
- RLS policies handle authorization

ERROR HANDLING:
- Consistent error format: { error: string }
- HTTP status codes: 200 (success), 400 (bad request), 401 (unauthorized), 500 (server error)
- Logging: console.error for debugging

RESPONSE FORMAT:
- Success: JSON object with data
- Error: JSON object with error message

7.3 WEBHOOK INTEGRATIONS

n8n Webhook (AI Receptionist):
POST /api/webhooks/n8n
Headers: Authorization: Bearer {N8N_WEBHOOK_SECRET}
Body: {
  business_id: UUID,
  customer_name: string,
  customer_phone: string,
  customer_email?: string,
  customer_address?: string,
  scheduled_start: ISO datetime,
  scheduled_end: ISO datetime,
  description?: string,
  urgency?: string,
  calendar_event_id?: string
}
Response: { success: true, job_id: UUID }

Stripe Webhook:
POST /api/webhooks/stripe
Headers: Stripe-Signature
Body: Stripe event payload
Handles: invoice.payment_succeeded, invoice.payment_failed

19.1 USEFUL SQL QUERIES

-- Get business metrics
SELECT 
  status,
  COUNT(*) as count,
  SUM(total_cost) as total
FROM jobs
WHERE business_id = 'UUID'
GROUP BY status;

-- Get revenue by month
SELECT 
  DATE_TRUNC('month', paid_at) as month,
  COUNT(*) as invoices,
  SUM(total) as revenue
FROM invoices
WHERE status = 'paid'
  AND business_id = 'UUID'
GROUP BY month
ORDER BY month DESC;

-- Get tech performance
SELECT 
  u.full_name,
  COUNT(j.id) as jobs_completed,
  SUM(j.labor_hours) as total_hours
FROM users u
LEFT JOIN jobs j ON j.technician_id = u.id
WHERE u.role = 'tech'
  AND u.business_id = 'UUID'
  AND j.status = 'completed'
GROUP BY u.id, u.full_name;
